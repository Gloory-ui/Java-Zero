# Контент курса

Каждый квест — папка в `content/quests/`, каждый этап — вложенная папка с номером.

```
content/quests/
  kt1/
    quest.yaml                 название, порядок, условие открытия, звание за прохождение
    01-multiplication-table/
      stage.yaml               заголовок, подсказки, квиз, вопросы защиты, тесты
      theory.md                теория (Markdown)
      pitfalls.md              частые ошибки
      Starter.java             код, с которого начинает студент
      Solution.java            эталонное решение
```

## Как добавить КТ 2

1. Скопируйте папку `content/quests/kt1` в `content/quests/kt2`.
2. В `quest.yaml` поменяйте `id: kt2`, название, `fileName` (например, `KT2.java`), `order` на следующий номер и `unlockAfter` на квест, после которого КТ 2 откроется.
3. Для каждого задания заведите папку `01-…`, `02-…` без пропусков в нумерации. `id` в `stage.yaml` совпадает с частью имени папки после номера.
   Номер этапа на странице («КТ 2 // ЗАДАНИЕ 03») задаёт шаблон `stageBadge` в `quest.yaml`, например `"КТ 2 // ЗАДАНИЕ {n}"`. `{n}` — номер этапа, `{total}` — число этапов в квесте.
4. Проверьте курс: `npm run content:check`.

Проверка компилирует решение и стартовый код тем же компилятором, что в браузере. Она требует, чтобы решение проходило все тесты, а стартовый код компилировался и проваливал хотя бы один тест. Для неё нужна установленная Java 17 или новее.

## Из чего состоит этап

- `theory.md` — 1500–3000 символов, на «ты», по разделам:
  - «Зачем это нужно» — какую задачу решает тема;
  - «Как это работает» — конструкция с коротким примером;
  - «Разбор: что выведет программа» — пример, который студент прогоняет в голове;
  - «Твоё задание» и «Что должна вывести программа» — точный вывод из тестов.
- `pitfalls.md` — 2–4 настоящие ошибки: неверный код и что скажет компилятор.
- В `stage.yaml`:
  - `hints` — три подсказки;
  - `quiz` — один вопрос;
  - `exam` — три вопроса защиты;
  - `memory` — вкладка «Память»;
  - `tests` — тесты этапа.
- Этап опирается только на то, что объяснили раньше. Если нужна новая конструкция, объясните её в теории этого этапа или добавьте этап перед ним.

## Новые этапы в пройденном квесте

Вставьте папку с нужным номером и сдвиньте номера папок после неё (`git mv`). `id` этапов не меняйте: по ним хранится прогресс студентов.

Новому этапу поставьте `isNew: true`. Если студент сдал этапы после него, этап получит на карте курса пометку «новый», а над картой появится объявление. Квест, в котором у студента уже есть сданные этапы, остаётся открытым, даже если в предыдущем квесте появились несданные этапы.

## Тесты этапа

```yaml
tests:
  # Ввод → вывод. Сравнение построчное, хвостовые пробелы не учитываются
  - name: Простые до 20
    stdin: |
      20
    stdout: |
      2 3 5 7 11 13 17 19
      Количество простых чисел: 8

  # Проверка структуры, когда по выводу её не видно. Комментарии в коде не считаются
  - kind: source
    name: Выход из цикла через break
    pattern: \bbreak\s*;
    message: Останови цикл оператором break
```

- `match` у теста с выводом:
  - `lines` (по умолчанию) — построчно, хвостовые пробелы не учитываются;
  - `tokens` — построчно по словам: число пробелов и табуляций и пустые строки не важны. Для таблиц и чисел через пробел: студент может печатать через `\t` или `printf`;
  - `exact`, `contains`, `regex` — для особых случаев.
- Во всех режимах «ё» равна «е»: «Чётное» и «Четное» засчитываются одинаково.
- Вывод, который ждёт тест, должен дословно стоять в теории в блоке «Что должна вывести программа». Иначе студент проваливает этап, даже выполнив условие.
- Если программа читает ввод через `Scanner`, добавьте в `stage.yaml` поле `sampleInput`: оно подставится в поле ввода при ручном запуске.
- В браузере Java работает с английской локалью: `nextDouble()` ждёт дробь через точку (`3.5`).

## Подсказки

```yaml
hints:
  - Направление мысли: какая конструкция нужна и зачем.
  - Устройство конструкции, например заголовок цикла `for (int i = 1; i <= 10; i++)`.
  - Почти готовый код одной-двух ключевых строк.
```

Студент открывает подсказки по одной. Полное решение показывает только кнопка «Решение» после пяти разных попыток, поэтому в подсказках целиком решение не пишем.

## Вкладка «Память»

```yaml
memory:
  note: Момент после цикла: суммы посчитаны.   # какой момент выполнения показан
  stack:
    - method: main()
      vars:
        - int sumEven = 30
        - Scanner sc → объект в куче
  heap:
    - obj: Scanner
      data: Читает числа из ввода.
```

- В стеке — переменные методов: простые значения (`int`, `double`, `boolean`, `char`) и ссылки.
- В куче — только настоящие объекты: строки, массивы, `Scanner`. Вывод на консоль и сами циклы в памяти не хранятся.
- Значения переменных — те, что будут в этот момент при запуске эталонного решения.
