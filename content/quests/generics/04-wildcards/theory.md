## Зачем это нужно

`Integer` — наследник `Number`. Кажется, что `List<Integer>` тогда — наследник `List<Number>`. Но нет: иначе в список целых можно было бы через `List<Number>` положить `3.14`. Чтобы метод всё-таки принимал списки разных типов, есть **шаблоны** со знаком вопроса.

## Как это работает

```java
static double sum(List<? extends Number> list) {   // список Number или его наследников
    double s = 0;
    for (Number n : list) {
        s += n.doubleValue();     // читать можно: каждый элемент точно Number
    }
    return s;
}

static void addOnes(List<? super Integer> list) {  // список Integer или его предков
    list.add(1);                  // писать Integer можно: он подходит к любому из них
}
```

-   `? extends T` — «T или наследник». Из такого списка можно **читать** элементы как `T`, но добавлять нельзя: неизвестно, какой именно тип внутри.
-   `? super T` — «T или предок». В такой список можно **добавлять** `T`, а читать — только как `Object`.
-   `?` без ограничения — любой тип, например для метода, который только печатает размер.

Правило для запоминания: **кто отдаёт — `extends`, кто принимает — `super`**.

## Разбор: что выведет программа

```java
List<Object> things = new ArrayList<>(List.of("x"));
addOnes(things);
addOnes(things);
System.out.println(things);
```

`List<Object>` подходит к `? super Integer`, ведь `Object` — предок `Integer`:

```text
[x, 1, 1]
```
