## Зачем это нужно

У процессора несколько ядер, а обычная программа выполняется по одной команде за раз и занимает одно ядро. Большую работу можно разделить на части и выполнять **одновременно** в нескольких **потоках**. Так же работают браузер, игра, сервер: один поток рисует экран, другой качает данные.

## Как это работает

```java
Thread worker = new Thread(() -> {       // что делать — лямбда Runnable
    System.out.println("Работаю в " + Thread.currentThread().getName());
});
worker.start();                          // запустить параллельно
worker.join();                           // дождаться окончания
System.out.println("Поток закончил");
```

-   `new Thread(задача)` только создаёт поток. Работать он начинает после `start()`.
-   `run()` вместо `start()` выполнит задачу в **текущем** потоке, никакой параллельности не будет.
-   `join()` ждёт, пока поток закончит. Без него `main` может напечатать результат раньше, чем он посчитан.
-   `join()` бросает проверяемое `InterruptedException`, поэтому у `main` пишут `throws InterruptedException`.
-   Лямбда в потоке может менять ячейки массива, объявленного снаружи: сама ссылка на массив при этом не меняется.

## Разбор: что выведет программа

```java
int[] box = new int[1];
Thread t = new Thread(() -> box[0] = 42);
t.start();
t.join();
System.out.println(box[0]);
```

`join` гарантирует, что поток уже записал число:

```text
42
```
