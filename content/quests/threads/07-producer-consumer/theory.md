## Зачем это нужно

Официант принимает заказы, повар готовит. Официант не должен стоять над поваром, а повар — бегать по залу. Между ними окошко для заказов. Это классическая схема **производитель — потребитель**, и в Java окошко называется `BlockingQueue`.

## Как это работает

```java
import java.util.concurrent.ArrayBlockingQueue;
import java.util.concurrent.BlockingQueue;

BlockingQueue<String> queue = new ArrayBlockingQueue<>(2);   // окошко на 2 заказа
queue.put("суп");          // положить; если места нет — ждать
String order = queue.take(); // взять; если пусто — ждать
```

-   `put` ждёт, пока в очереди освободится место. Быстрый производитель не завалит медленного потребителя.
-   `take` ждёт, пока появится элемент. Потребителю не нужно крутить пустой цикл с проверками.
-   Чтобы сообщить «заказов больше не будет», кладут особый элемент-**сигнал**, например «СТОП».
-   `put` и `take` бросают `InterruptedException`. В лямбде `Runnable` его приходится ловить: `catch (InterruptedException e) { Thread.currentThread().interrupt(); }`.
-   Неблокирующие `offer` и `poll` не ждут: `offer` вернёт `false`, если места нет, `poll` — `null`, если пусто.

## Разбор: что выведет программа

```java
BlockingQueue<Integer> q = new ArrayBlockingQueue<>(1);
Thread p = new Thread(() -> {
    try {
        q.put(1);
        q.put(2);            // ждёт, пока main заберёт 1
    } catch (InterruptedException e) {
        Thread.currentThread().interrupt();
    }
});
p.start();
System.out.println(q.take() + q.take());
p.join();
```

```text
3
```

## Твоё задание

Сейчас официант кладёт заказы через `offer`, и если окошко занято, заказ молча теряется. Переделай его на `put`, а после пятого заказа пусть кладёт сигнал «СТОП».

Повар — поток `main`. Он берёт заказы через `take` и печатает «Готовлю: …», пока не получит «СТОП». В конце выведи, сколько заказов приготовлено.

### Что должна вывести программа

```text
Готовлю: заказ 1
Готовлю: заказ 2
Готовлю: заказ 3
Готовлю: заказ 4
Готовлю: заказ 5
Все заказы готовы: 5
```
