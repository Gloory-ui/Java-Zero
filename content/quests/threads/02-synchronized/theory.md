## Зачем это нужно

Два кассира одновременно продают последнее место в зале: оба видят «осталось 1», оба продают, в итоге −1. Когда потоки вместе меняют общие данные, изменения теряются или портятся. Это **гонка**. `synchronized` пускает в опасный участок кода только один поток за раз.

## Как это работает

`count++` выглядит одним действием, но это три шага: прочитать, прибавить, записать. Два потока могут прочитать одно и то же значение, и одно прибавление потеряется.

```java
class Counter {
    private int count;

    synchronized void increment() {   // одновременно выполняет только один поток
        count++;
    }

    int get() {
        return count;
    }
}
```

-   `synchronized` у метода запирает объект на время вызова. Другие потоки ждут у входа.
-   Блок `synchronized (obj) { ... }` запирает только нужный участок и выбранный объект.
-   Обычный `ArrayList` не рассчитан на запись из нескольких потоков. Запись в него оборачивают в `synchronized`.

В этой лаборатории Java работает в браузере, и потоки переключаются реже, чем на настоящей JVM. Гонка здесь может не проявиться, но в настоящей программе без `synchronized` счётчик почти наверняка недосчитается.

## Разбор: что выведет программа

```java
List<Integer> log = new ArrayList<>();
Runnable task = () -> {
    for (int i = 0; i < 3; i++) {
        synchronized (log) {
            log.add(i);
        }
    }
};
Thread a = new Thread(task), b = new Thread(task);
a.start(); b.start(); a.join(); b.join();
System.out.println(log.size());
```

Каждый поток добавил по три числа, ни одна запись не потерялась:

```text
6
```
