## Зачем это нужно

Если поля класса открыты, любой код может записать коту возраст −1000 лет, и объект окажется в бессмысленном состоянии. В команде так и бывает: коллега пишет `barsik.age = -1000;`, и ошибка всплывает далеко от места, где её сделали. Решение — закрыть поля и пускать к ним только через методы, которые проверяют значения.

## Как это работает

```java
class Cat {
    private String name;       // private — доступ только внутри класса Cat
    private int age;

    Cat(String name, int age) {
        this.name = name;
        this.age = age;
    }

    public String getName() { return name; }     // геттер — чтение
    public int getAge() { return age; }

    public void setName(String name) { this.name = name; }   // сеттер — запись

    public void setAge(int age) {
        if (age >= 0) {
            this.age = age;
        } else {
            System.out.println("Ошибка: возраст не может быть отрицательным");
        }
    }
}
```

-   **`private`** — самый строгий модификатор: поле видно только внутри своего класса. `barsik.age = -1000;` в `main` больше не скомпилируется.
-   **Геттер** `getAge()` отдаёт значение, **сеттер** `setAge(...)` принимает новое и может его проверить. Названия по договорённости: `get` или `set` плюс имя поля.
-   Неверное значение сеттер не записывает, поле сохраняет старое.
-   Геттеры и сеттеры пишут с умом: если поле нужно только читать, достаточно геттера.

## Разбор: что выведет программа

```java
Cat c = new Cat("Том", 2);
c.setAge(-5);
c.setAge(4);
System.out.println(c.getName() + " " + c.getAge());
```

`-5` отклонён с сообщением об ошибке, `4` записан. Выведется сообщение об ошибке, а затем `Том 4`.
