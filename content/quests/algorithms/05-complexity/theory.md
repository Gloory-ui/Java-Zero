## Зачем это нужно

Программа быстро работает на ста записях и зависает на миллионе. Чтобы предсказать это заранее, алгоритмы сравнивают по тому, как растёт число операций вместе с размером данных. Эту оценку записывают через **O большое**.

## Как это работает

| Оценка | Как растёт | Пример |
| --- | --- | --- |
| O(1) | не зависит от n | взять `a[5]` |
| O(log n) | +1 шаг при удвоении n | бинарный поиск |
| O(n) | вдвое больше при удвоении n | перебор массива |
| O(n log n) | чуть быстрее, чем линейно | сортировка слиянием |
| O(n²) | вчетверо больше при удвоении n | пузырёк, все пары элементов |

-   Константы не пишут: O(2n) — это тоже O(n). Важно, как растёт, а не сколько точно.
-   Для n = 1 000 000 разница огромная: O(log n) — 20 операций, O(n) — миллион, O(n²) — триллион.
-   Число шагов бинарного поиска — сколько раз n можно поделить пополам до нуля.

Большие числа вроде 500 миллиардов не помещаются в `int` (максимум около 2,1 миллиарда). Для них нужен `long`: `(long) n * (n - 1) / 2`.

## Разбор: что выведет программа

```java
int n = 16, steps = 0;
while (n > 0) {
    steps++;
    n /= 2;
}
System.out.println(steps);
```

16 → 8 → 4 → 2 → 1 → 0, пять делений:

```text
5
```

## Твоё задание

Допиши три метода, которые считают число операций для размера `n`:

-   `linearSteps` — перебор в худшем случае, `n` сравнений;
-   `binarySteps` — сколько раз `n` делится пополам до нуля;
-   `pairSteps` — сколько разных пар элементов: `n × (n − 1) / 2`, в `long`.

### Что должна вывести программа

```text
n = 8: линейно 8, бинарно 4, пары 28
n = 1024: линейно 1024, бинарно 11, пары 523776
n = 1000000: линейно 1000000, бинарно 20, пары 499999500000
```
