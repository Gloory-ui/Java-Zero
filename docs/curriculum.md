# План курса Java-Zero

Порядок тем от первой программы до многопоточности и итогового проекта. Каждый квест — 5–10 этапов
по шаблону из `content/README.md`: теория, грабли, квиз, три вопроса защиты, три подсказки, тесты.
Контрольные точки (КТ) в план не входят. Места под них отмечены: когда придёт билет, КТ встаёт
сразу после квеста, который закрывает её темы.

## Правила

- Этап опирается только на то, что объяснили раньше. Если в задании нужна новая конструкция,
  её объясняют в теории этого этапа или добавляют этап перед ним.
- Квесты открываются по цепочке `unlockAfter`. КТ — боковая ветка: она открывается после своего
  подготовительного квеста, а следующий учебный квест её не ждёт. Студент готовится к КТ,
  когда она нужна ему в вузе, а курс не стоит на месте.
- id этапов после выкатки не меняются: по ним хранится прогресс. Новые этапы в пройденном
  квесте получают `isNew: true` (см. `content/README.md`).
- Звание за квест (`rank` в `quest.yaml`) — это титул. Его не путать с рангами уровня
  из `lib/game/ranks.ts`: названия не должны совпадать.
- Опыт: этап ≈ 70 XP, задание КТ ≈ 110 XP. Кривая уровней рассчитана на курс примерно
  из 170 этапов вместе с КТ; баланс проверяет `tests/unit/gamification.test.ts`.

## Порядок работы

1. **Массивы и таблицы (03)** и **Классы и объекты (04)** — примеры из лекций (`Cat barsik`, `Truck`,
   `TimeMachine`, `Proba`). Билеты КТ 2 и КТ 3 уже есть; они встанут боковыми ветками, когда ты скажешь.
2. **Наследование (05)** — по лекции «Конструкторы базовых классов».
3. Дальше по таблице, по одному-два квеста за выкатку. Каждый квест проходит `npm run content:check`
   на настоящем JDK и ручную проверку в браузере.

## Как добавить КТ, когда придёт билет

1. Найти в таблице квест, который закрывает темы билета. Если какой-то темы нет, сначала добавить
   этап в подготовительный квест.
2. Создать `content/quests/ktN/`: `quest.yaml` с `unlockAfter: <подготовительный квест>`,
   `stageBadge: "КТ N // ЗАДАНИЕ {n}"`, титулом за КТ и файлом `KTN.java`. Формулировки билета не менять.
3. Каждое задание — этап с блоком «Что повторить» (ссылки на этапы подготовки) и тестами.
   Случайные данные проверяются через `match: regex`, данные с ввода — через `stdin`.
4. `npm run content:check`, юнит- и e2e-тесты, ручной проход.
