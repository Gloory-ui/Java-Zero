# Админка

Адрес — `/admin`. Вкладки: «Обзор» (статистика), «Квесты» (правки текстов), «Лидерборд» (модерация),
«Группа» (доступ к разделу и прогресс по КТ). Страница закрыта от поиска; данные отдают только функции базы
и маршруты `/api/admin/*`, которые сами проверяют, что пользователь — админ.

## 1. SQL — в Supabase → SQL Editor

1. `supabase/migrations/20261001120000_admin_core.sql` — админы, честная таблица лидеров, правки текстов.
2. `supabase/migrations/20261001130000_group_access.sql` — доступ к «Группе».
3. `supabase/migrations/20261001140000_admin_stats.sql` — статистика для «Обзора».

Первым — `admin_core`: остальные проверяют права через его `is_admin()`. 2-я и 3-я миграции друг от друга не
зависят и идут в любом порядке.

Каждый файл целиком, повторный запуск безопасен. Код сайта выкатывается после SQL: без таблиц админка
покажет ошибку, а сайт для студентов продолжит работать.

## 2. Назначить себя админом

В SQL Editor, подставив свой ник (как в адресе профиля `/u/ник`):

```sql
insert into public.admins (user_id)
select id from public.profiles where handle = 'ваш_ник'
on conflict do nothing;

-- проверка: должна вернуться одна строка с вашим ником
select p.handle from public.admins a join public.profiles p on p.id = a.user_id;
```

Снять права: `delete from public.admins where user_id = (select id from public.profiles where handle = 'ник');`

## 3. Честная таблица лидеров

Студент сам пишет в базу свои этапы и достижения (так работает синхронизация), поэтому раньше можно было
вписать себе выдуманные этапы или лишний опыт. Теперь опыт в лидерборде и публичном профиле считается только
по **каталогу** `xp_catalog`: все настоящие этапы, достижения и квесты дня курса с честным максимумом опыта
(этап — 70 XP, задание КТ — 110 XP). Квесты дня, присланные задним числом, в рейтинг не идут.

- Каталог обновляется сам при каждом запуске сайта на Render (`instrumentation.ts`, нужен
  `SUPABASE_SERVICE_ROLE_KEY`). В логах Render после выкладки — строка `xp_catalog: N строк`.
- Опыт на самом сайте у студента не меняется: каталог влияет только на лидерборд и публичный профиль.

Проверка после SQL — нет ли у честных студентов строк, которых нет в каталоге (например, старых id):

```sql
select sp.quest_id || '/' || sp.stage_id as stage, count(*) from public.stage_progress sp
where sp.passed_at is not null
  and not exists (select 1 from public.xp_catalog c where c.kind = 'stage' and c.id = sp.quest_id || '/' || sp.stage_id)
group by 1 order by 2 desc;

select a.achievement_id, count(*) from public.achievements a
where not exists (select 1 from public.xp_catalog c where c.kind = 'achievement' and c.id = a.achievement_id)
group by 1 order by 2 desc;
```

Если там массово встречается id, который выглядит честным (старое название этапа), — скажите Claude, он
добавит его в каталог.

## 4. Вкладки

- **Обзор** — плитки (ученики, активные, сданные этапы, учатся) с изменением к прошлому периоду, активность по
  дням или неделям, воронка курса и самые трудные этапы. Активный — оставил след: открыл или сдал этап, сохранил
  код, получил достижение, закрыл квест дня. Этапы считаются по каталогу `xp_catalog`. Дни — по часовому поясу
  браузера админа. Без миграции `admin_stats` вкладка подскажет, какой файл выполнить.
- **Лидерборд** — все студенты, включая снятых. Видно опыт «по каталогу» и «как в базе»; разница, «чужие строки»
  (id, которых нет в курсе) и «N этапов за час» подсвечены как признаки накрутки. «Снять с рейтинга» убирает
  студента из таблицы лидеров с причиной (видна только админам), «Вернуть в рейтинг» — обратно. Прогресс
  студента при этом не меняется.
- **Квесты** — правки поверх файлов курса: названия квестов и этапов, подзаголовок, теория, частые ошибки,
  подсказки, вопрос и подсказка квиза. На сайте правка появляется при следующем открытии страницы этапа и карты
  курса (не позже чем через минуту). «Вернуть из файла» убирает правку. Код, тесты, варианты ответов и новые
  этапы меняются в репозитории — их проверяет настоящая Java (`npm run content:check`).
